> ## v0.4.9：修掉一个「绿鞋自解析根本跑不起来」的资源声明缺失 + 全库静态审计（2026-09-27）
>
> 老板要求「再严查一遍有没有 bug」。这一轮我不再肉眼看，而是**建了静态契约审计脚本**穷尽式扫描，
> 结果抓到一个确凿的功能性 bug。

> **一、真 bug：pdf.js 主库没写进 `web_accessible_resources`**
> `core.js` 用动态 `import(chrome.runtime.getURL("vendor/pdf.min.mjs"))` 加载 pdf.js 主库来解析招股章程。

> ## v0.4.6：把「覆盖包络」改成真正的预测 —— 中枢优先 + 50% 分位区间（2026-09-26）
>
> 老板原话：「**你预测的区间那么大，其实等于没有预测**」—— 一针见血，是我把两种区间搞混了。
>
> **一、诊断：旧区间既宽又不准**
> 用 106~110 只带暗盘实测的样本量化：
>
> | | 旧口径 |
> |---|---|
> | 区间平均宽度 | **48.0 pt**（最宽 70） |
> | **实际命中率** | **43.6%** |
> | 中枢点估计误差（中位） | 27.3 pt |
> | 残差中位数 | **−8.0 pt**（一半的股票比预测低 8pt 以上） |
>
> 三个根因：
> ① 区间是 `均值 ± 该档标准差` —— 那是「最好/最坏可能」的**覆盖包络**，不是预测区间；
> ② 中枢用**均值**，被妖股右尾拉高（100–500 倍档：均值 +22.9 vs 中位 **+2.4**）→ 系统性高估；
> ③ **六个修正项全部叠加**：消融实测，叠加后命中率由 46.2% 掉到 **36.8%**、误差由 23.7 掉到 24.8pt；
>    缩放系数 k 从 0→1 **单调变差，k=0 最好**。根因之一是**保荐人战绩 / 基石占比按「首日」标定，
>    却用在预测「暗盘」的 S2 上** —— 口径不符（S3 标的才是首日，这两项在 S3 保留）。
>
> **二、改法：按样本分位数重做，且只保留实测有效的项**
> · **中枢 = 该条件集的中位数**（右偏分布下比均值更贴近"最可能落点"）；
> · **区间 = 该条件集的 [P25, P75]**（**不对称**：下侧 dLo、上侧 dHi 分开给，直接吃掉右偏）；
> · **S2 只保留「大盘环境」**（唯一实测有增益：命中 48.1% > 基线 46.2%）；
>   赛道 / 国配 / 规模 / 保荐人 / 基石改为「**仅参考、不参与 S2 打分**」，并在步骤里写明原因；
> · 置信星级改由**区间宽度**决定（越窄越可决策），缺超购时封顶 ★★☆。
>
> **三、效果**

> ## v0.4.5：工坊加宽 + A+H 折价锚按 38 只样本重标定 + 散户中签率（2026-09-26）
>
> 老板四条意见，逐条给了**可核验的依据**。
>
> **一、「这个可以做的更宽一点！不太好看啊」—— 找到真凶：响应式用错了基准**
> 面板是**固定宽度侧栏**（440~860px），可内部布局却用 `@media (max-width: 820px)` 按**视口**判断 ——
> 1460 视口下永远不触发，于是 440px 的面板硬排 3 列卡（每张 137px），文字被截成「降级估算：未…」。
> 两处修正：
> · **改用容器查询**（`@container`）：列数与列宽只取决于面板自身宽度 → 440px 时自动 2 列，860px 时 3 列；
> · **上限 620 → 860px**（左栏占位固定 1020px，其余全给工坊；**站点 .app 的 960px 一字未动**）。
> 实测 1920 视口：面板 **620 → 860px**，三张卡各 269px，零重叠；1460 视口：面板 440px 自动 2 列。
>
> **二、「A/H 股有折价存在，发行价不可能破发很多」—— 一半对，一半数据不支持**
> 用 **38 只 A+H 标的**、一律取**招股截止日前最后一个交易日的 A 股收盘价**（消除用现价回测的前视偏差）标定：
>
> | 折价（A 较发行价溢价） | 样本 | 暗盘均值 | 暗盘最差 |
> |---|---|---|---|
> | 0~20% | 6 | +6.26% | −4.95% |
> | 20~40% | 6 | −0.73% | −9.21% |
> | **≥40%** | 21 | **+17.87%** | **−21.26%** |
>
> 回归：`暗盘% = −0.82 + 0.238 × 折价%`（r = 0.396）。**折价越深、暗盘均值越高 → 老板的方向判断对**；
> 但 **不是「不会破发」的保证**：样本里暗盘 < −5% 的 4 只中，**3 只折价落在 38~44%**（与 03757 的 41.5% 同区间），
> 折价最深（79.7%）的滨化股份暗盘 **−21.26%**。所以这次**只抬中枢、不设地板**。
> 旧实现是「clamp(溢价, ±15) 再按 25% 权重混合」→ 最大只贡献 ±3.75pt，等于把最硬的信息削平。
> 改为按回归斜率：`A+H 折价锚 = clamp(0.238 × 溢价, ±12)`。03757 因此由 **+3.75 → +9.88**。
>
> **三、「S2 预测价格出入有点大」—— 下沿 −31.90% → −19.80%**
> 两处叠加：① 中枢按上面的标定上移（03757 的 S2 基准 ≈ −1.9% → **+4.2%**）；
> ② 空窗期降级时有折价锚 → 半宽由 ±30 收窄到 **±24**（依据：折价 ≥40% 的 21 只样本暗盘 sd ≈ 22pt，留余量）。
> 修后 03757 S2 = **31.510 – 40.739 港元（−19.80% ~ +28.20%）**，下沿正好落在同区间样本最差值（−17.31%）附近 ——
> 区间宽 48pt，不再是原来那个 60pt 的"什么都包得住"。
>
> **四、「散户中签率是不是影响暗盘的重要因素」—— 不是独立因子，已放入「只展示」**
> 用站点自带的 107 只中签人数做了检验：
> · 与超购倍数**高度共线**：log10(超购) vs log10(中签率) **r = −0.72**（中签率本就是超购经回拨后的结果）；
> · **单独解释力更弱**：对暗盘，超购 r = **+0.464** > 中签率 −0.397（甲组 −0.355）；

- **三列追加在最右**，站点原有列序 / 列宽 / 行高不动；窗口够宽时**无需横向滚动**。
- **列状态语义（纯函数，零记忆）**：未到阶段显「—」；**已过阶段保留数值并置灰**（灰显即失效，可回溯）；当前阶段琥珀金描边高亮；数据未公布显「待公布」。
- **悬浮任一预测格**：弹出摘要卡（锚 / 关键因子 / 区间 / 置信度 / 模型未纳入项）。人工设定的格会显示你的区间、备注与设定时间。
- **点任一格**：进详情页（站点原本就是整行点击跳转，未改动此行为）。

### 详情页「预测工坊」

页面顶部（站点「基本信息」卡之前）插入一块工坊卡片，五个区块：

| 区块 | 内容 |
|---|---|
| 三阶段预测 | 三张卡：模型区间 + 涨跌幅 + 置信度星级 + 状态（当前 / 已过 / 未到 / 已出实测）；每张卡有「改价」 |
| 计算过程 | 当前阶段的**逐项增量表**（每步都写明理由），末尾给出「修正后基准」与「展开区间」 |
| 实测数据 | 暗盘收盘 / 首日收盘（**只读**，标注站点口径） |
| 复盘 | 你设过且已有实测时，给出「你的设定 vs 实际」与高估/低估点数 |
| 模型因子 | 三段呈现：**已纳入 8 项** + **只展示（不入权重）3 项** + **未纳入 2 项及原因** |
| 招股书数据 | 基石配售（占比 vs 基准 35%）与**超额配股权（绿鞋：股数 / 占比 / 稳价人）**，各自说明是否参与打分；底部附**披露原文直链** |
| 散户中签率 | 整体 / 甲组 / 乙组（**人数口径**，配售结果公布后出现），并当场写明为何只展示不加权 |

**改价**：点任一阶段卡的「改价」→ 填区间（下沿/上沿，可填 `25.5` 或 `+50%`；只填一个＝单点）→ 可加备注 → 保存。卡片即刻变为「✎ 人工设定」并提供**「恢复模型值」**。工坊头部有「刷新数据」与「收起」。

### Popup 设置（点扩展图标）

- A→H 汇率（CNY→HKD，默认 1.09）
- 启用实时大盘行情（恒指 + A 股比价，默认开）
- **模拟日期**：填某日可预览该日三列行为与置灰效果，留空 = 今天

### 阶段判定（纯函数，零记忆）

| 时点 | 阶段 | 三列表现 |
|---|---|---|
| 今天 ≤ 招股截止 | S1 | 第 1 列亮 |
| 招股截止 → 配售结果未公布（空窗期） | S1 | 仍按招股书口径 |
| 配售公布 → 暗盘日 18:30 前 | S2 | 第 2 列亮 |
| 暗盘日 18:30 后 → 上市日前 | S3 | 第 3 列亮；**第 2 列转实测暗盘** |
| 今天 ≥ 上市日 | LISTED | 第 1 列灰显保留；**第 2 列实测暗盘、第 3 列实测首日** |

## 三、模型与依据

因子权重与「超购倍数 → 暗盘涨幅」的经验映射，**均来自 2024–2026 共 106 只真实港股新股样本校准**（`node tools/backtest.js` 可复跑）。

**S2（核心）计算过程示例**（05287 超购 356.2 倍）：

| 步骤 | 说明 | 增量 |
|---|---|---|
| 超购分档基准 | 落入 500–1000 倍档（106 只样本该档均值 +21%） | +21.0% |
| 赛道修正 | 名称含科技/半导体关键词（**名称推断**，站点无行业字段） | +8.0% |
| A+H 折价锚 | A 股较发行价的溢价 × 回归斜率 **0.238**（38 只样本标定），截断 ±12pt | ±x.x% |
| 国配修正 | 国际配售超购 >5 倍 → 机构认购踊跃 | +3.0% |
| 大盘环境 | 恒指涨跌幅 × 0.3 | −0.3% |
| 发行规模 | 发行额 <30 亿港元 → 小盘易炒 | +3.0% |
| **修正后基准** | 上述汇总（含上下界夹逼 [−40%, +400%]） | **+34.7%** |
| **展开区间** | 基准 ± 22%（该档样本历史离散度） | **+12.7% ~ +56.7%** |

- **S2**（v0.4.6 换口径）：**中枢 = 该超购档位样本的中位数**，**区间 = 该档位的 [P25, P75]**（不对称，真实的 50% 中央区间）。只再叠加恒指修正 —— 赛道 / 国配 / 规模 / 保荐人 / 基石经消融实测对暗盘无增益（见 v0.4.6 变更日志），改为「仅参考、不参与」。实测：**命中 48.2%**（名义 50%）、点估计误差中位 **24.9 pt**、残差中位数 **+0.3 pt**（无系统性偏差）。
  ⚠️ 区间宽度随档位天差地别：超购 <100 倍约 **6~8 pt**（很可决策），超购 >1000 倍 **55~105 pt**（妖股本就无规律）。**宽 = 这只真的没把握**，不是模型偷懒。
- **S3**：以暗盘实际涨幅为锚，妖股（暗盘 >50%）向下收窄、破发股延续偏弱，叠加隔夜恒指。保荐人战绩与基石占比按「首日」标定，与 S3 标的口径一致，**在 S3 保留并加权**。
- **S1**：无超购数据，按赛道 / 机制 / 入场费 / A+H 锚给方向性宽区间，明确低置信（不给点估计 —— 信息不足以支撑一个"落点"）。

### 已纳入的 8 个因子

超购分档 · 赛道修正（名称推断）· **A+H 折价锚**（38 只样本回归标定）· 国配超购 · 大盘环境 · 发行规模 · **保荐人战绩**（etnet）· **基石配售**（港交所招股章程）

### 只展示、不入权重（3 项）

**超额配股权（绿鞋）** · **发售结构** · **散户中签率**

> · **绿鞋**：招股章程里的「超額配股權」条款 —— 已完整抓取**授出股数 / 占全球发售比例 / 稳定操作人**，在工坊里单列展示并解释托价机制。港股 IPO 绝大多数都设、**区分度低**，故不入权重；但它回答的是「**有没有人在破发时托价**」，是独立于涨跌幅预测的重要信息，所以必须看得见；
> · **发售结构**：公开发售 / 国际配售的比例与回拨机制，用于判断货源集中度；
> · **散户中签率**（v0.4.5 新增）：整体 / 甲组 / 乙组。**与超购倍数高度共线**（log10 相关系数 −0.72），对暗盘的单独解释力也更弱（超购 r=+0.46 > 中签率 −0.40），两者同进回归只多 2.6pp R² 且系数符号不稳定 → **不加权，只展示**。它影响的是「你能拿到多少货」，不是「暗盘会涨多少」。口径为站点自带的**人数口径**，非交易所的「一手中签率」。

### ⚠ 仍未纳入的 2 项

**国配明细（长线基金占比）** · **未上市股的开盘价**

> · **国配明细**：招股章程与所有免费源都**不披露认购人结构**（谁是长线基金）—— 那是付费数据商的内容；
> · **未上市股的开盘价**：**客观不可能**（尚未发生）；已上市股的已由 etnet 补齐。
> 这些缺口模型**看不见** —— 这正是「改价」存在的意义：把你知道、模型不知道的信息补进去。

### 基石配售因子怎么算的（可核查）

1. 取该股的**招股章程 PDF 链接** —— 直接读 **i668 接口的 `prospectus_url`**（117/117 全覆盖，就是详情页时间线里的「招股书 PDF ↗」）；
2. 提取「基石配售」段落的**基石认购股数**；
3. **基石占比 = 基石认购股数 ÷ 全球发售股数**（分母用 i668 的 `shares_offered`，已与 etnet 的"發售股份數目"核对一致）；
4. 修正量 = `(基石占比 − 市场基准 35%) × 保守权重 0.12`，截断 **±6pt**；
5. 交叉验证：09856 算出 **47.0%**，招股书自述 **47.02%** ✓；03228 算出 47.7% ✓。

> 权重刻意取保守值：占比与首日涨幅并非线性关系，且该权重尚未经完整样本校准 —— 界面上如实标注为「保守权重」。

### 保荐人战绩因子是怎么算的（可核查）

1. 从 etnet「保荐人表现」榜抓取每家保荐人的**保荐数目 / 首日上升概率 / 平均首日升跌**；
2. 个股页 `ipo-info.php?code=<4位代码>&tab=sponsor` 列出该股保荐人，与名录做**名称匹配**；
3. 多保荐人时按样本数**加权平均**；
4. 修正量 = `(该股保荐人平均首日 − 市场基准) × 权重`，权重 S1/S2 取 **0.15**、S3 取 **0.20**，并截断 **±8 / ±10 个百分点**；
5. 全过程写进「计算过程」表 —— 你能看到"中金+摩根士丹利，历史首日 +45.67%（65 间样本）vs 基准 +50.74% → −0.76%"这样的**具体数字**，而不是一句"已考虑保荐人"。

> 权重刻意取小值：这是**统计值**不是个股确定性，不该主导预测。

详细方法论见工作区 `港股打新开盘预测体系/` 下的三阶段文档。

## 四、数据来源与隐私

- **新股结构化数据**：复用站点自带签名直接调用其 `/api/ipo-stocks`（HMAC-SHA256，密钥为站点前端公开常量），扩展自驱取数。
- **实时行情**：腾讯 `qt.gtimg.cn`（恒指 + A 股比价），免费、公开、允许跨域。
- **免费因子库（保荐人战绩 / 首日开盘价）**：数据源是 **etnet 經濟通**的公开免费页面 ——
  - 保荐人战绩榜 `https://www.etnet.com.hk/www/tc/stocks/ipo-sponsor-performance.php`
  - 个股 IPO 页 `https://www.etnet.com.hk/www/tc/stocks/ipo-info.php?code=<4位代码>[&tab=sponsor]`

  ⚠️ **关键设计：本插件运行时不请求 etnet。** 数据由 `tools/fetch-etnet.py` 抓取后
  生成本地文件 `data/extras.js`，随插件一起加载。好处是：不跨域、不依赖对方接口稳定性、
  不给对方站点添请求压力。要更新数据，自己跑一次脚本即可：

  ```bash
  python3 tools/fetch-etnet.py            # 全量重建 data/extras.js
  python3 tools/fetch-etnet.py --quick    # 只抓最新 30 只（快）
  ```

- **基石配售 / 超额配股权**：数据源是**招股章程 PDF**（由港交所披露易托管）——
  这是免费公开渠道里**唯一**有基石投资者数据的来源。
  （实测：etnet 的「基石投資者」栏目是空的、AAStocks 只有保荐人与包销商、辉立 poems 与 aipo 也没有。）

  **PDF 链接不用自己找**：i668 接口顶层就给了 `prospectus_url`（招股章程，117/117）与
  `allotment_pdf_url`（配售结果公告，109/117），详情页时间线里的「招股书 PDF ↗」就是前者。
  脚本**优先用站点挂的链接**；只有站点没挂时才回退到披露易四步检索（代码 → stockId → 标题搜索 → 挑 PDF）——
  那条路又慢又会挑错文件（17 只曾挑到几十页的「延迟上市公告」）。

  每份章程提取三项：**基石认购股数**（→ 占比）、**超额配股权**（有无 / 授出股数 / 占比 / 稳定操作人）、**发售结构**。
  提取带**可信性防护**：页数 <100（会误命中 3 页的「延迟上市公告」）或 基石股数 > 全球发售股数 → 整条丢弃；
  股数正则锚定定义条款「**「超額配股權」指…**」并排除并存的「發售量調整權」，占比正则锚定股数附近，避免抓到经纪佣金。
  **工坊「招股书数据」区底部会透出披露原文直链**（招股章程 / 配售结果公告），可点开自行核对。

  ```bash
  # ⚠️ 本脚本需要 pymupdf，系统 python3 里没有装（装了也会报 "No module named 'pymupdf'"）。
  #    用托管 venv 的解释器跑；脚本已内置依赖自检，跑错解释器会直接提示正确路径。
  PY=~/.workbuddy/binaries/python/envs/default/bin/python
  $PY tools/fetch-prospectus.py --active      # 只抓「招股中」的（快，推荐日常用）
  $PY tools/fetch-prospectus.py              # 抓 i668 列表里的全部股票（慢，每只 6–30MB PDF）
  $PY tools/fetch-prospectus.py --codes 06802,03228
  ```

  ⚠️ 抓取失败**不会**清空已有数据（v0.4.3 修）：某只抓不到时保留上次成功的结果，只打印告警。

  同样**运行时不请求披露易**：抓下来写进同一个 `data/extras.js` 随插件加载。
  两个抓取脚本会**互相保留字段**，先后跑都行，不会覆盖对方的数据。
- **实测值口径（如实告知）**：i668 站点只提供 `dark_pool_change_pct`（暗盘收盘）与 `first_day_close_price`（首日收盘）。而 **S3 的预测标的是首日开盘价**，故插件优先用 etnet 的「首日開市升跌」显示**首日开盘**价；取不到时才回退 i668 的收盘价，并**明确标注为「首日收盘」**，两种口径不混用。（交叉验证：09856 的 etnet 首日收盘 +4.612% 与 i668 的 +4.61% 一致，说明数据源可靠。）
- **实测值口径（如实告知）**：站点接口只提供 `dark_pool_change_pct` 与 `first_day_close_price`。站点「暗盘VS首日」页原话是「**暗盘涨幅取当日暗盘收盘价，首日涨幅取上市首日收盘价**」—— 所以本插件的「实测暗盘 / 实测首日」是**收盘**口径，**不是开盘价**。翻遍站点前端全部 chunk，**不存在任何「开盘价」字段**；港股暗盘为场外交易，也无免费公开的开盘价源。故不做标题党式的"开盘价"标注。
- **纯前端、免费、离线加载；改价数据只存在本机 `chrome.storage.local`（未装扩展时降级 localStorage），不向任何第三方上传。**

## 五、已知局限

1. **免费不可得的只剩两类**：**国配明细（认购人结构 / 长线基金占比）** —— 所有免费源都不披露，属付费数据商内容；**未上市股的开盘价** —— 尚未发生，客观不存在。模型按「中性」处理（详见上文），**请用「改价」补充你的信息**。
   （基石 / 保荐人 / 绿鞋 / 中签率 / 已上市股开盘价五项均已补齐：基石与保荐人入权重，绿鞋、发售结构、散户中签率为「只展示」。）
2. 预测是**概率加权**而非精确报价；高倍超购妖股波动极大，置信度已分级提示。
3. 站点为 Element UI `el-table`（Vue 托管）。若其前端改版导致表结构或详情页卡片结构变化：列表侧浮条会如实报「未匹配到新股表格（页面结构可能已变化）」；工坊侧会显示「未能取得该股数据」。渲染异常一律**逐格降级**（出错格显 `!`），并在浮条附 `⚠ N 类异常` 计数，不静默、不拖垮整表。
4. **改价是主观判断，不是模型结论**；工坊中人工值一律带「✎ 人工设定」标记，与模型值配色区分。
